# HomeworkParser: перенос PostgreSQL в Aiven

Этот документ описывает перенос только хранилища HomeworkParser. Он не запускает E-school, Classroom или Telegram и не меняет Render.

## Короткий ответ

Одной замены `HOMEWORK_DATABASE_URL` недостаточно: новая база будет пустой. Сначала нужно скопировать `database_meta`, `homework_tasks` и `classroom_task_tombstones`, проверить статусы, fingerprints, snapshot’ы и pending-уведомления, а затем сделать cutover.

Приложение использует стандартный PostgreSQL через `pg`. Для Aiven Free используется обычный Service URI с `sslmode=require`; PgBouncer не нужен, потому что приложение ограничивает собственный пул двумя соединениями.

## Что нужно сделать владельцу аккаунта

1. Убедиться, что Aiven-сервис запущен, выбран тариф `Free`, база назначения пустая, а подключение разрешено с компьютера и Render.
2. Скачать в Aiven `Overview → Connection information → CA certificate → Download` и сохранить сертификат локально, например в `C:\Temp\homeworkparser-aiven-ca.pem`. Не вставлять сертификат в чат и не коммитить его.
3. Временно сохранить две строки подключения и путь к CA-сертификату в локальном `.env`. Файл уже исключён из Git; строки нельзя отправлять в чат или коммитить:

   ```dotenv
   SOURCE_DATABASE_URL=postgresql://...neon...?...sslmode=require
   AIVEN_DATABASE_URL=postgresql://...aiven.../defaultdb?sslmode=require
   HOMEWORK_DATABASE_CA_CERT_PATH=C:\Temp\homeworkparser-aiven-ca.pem
   ```

   Если `SOURCE_DATABASE_URL` не задан, скрипт использует существующий `HOMEWORK_DATABASE_URL`.
4. Не удалять Neon и не отзывать его пароль до завершения проверки и хотя бы одного полного рабочего цикла после cutover.

Пароль Aiven не нужно раскрывать кнопкой `eye` в консоли. На скриншоте Aiven также показан `IP address allowlist: Open to all`; после миграции его следует ограничить, если это совместимо с исходящими адресами Render.

## Подготовка и проверка

Работать нужно из корня репозитория на поддерживаемом Node.js `24.21.x`.

Сначала остановить единственный Render-процесс бота или перевести его в состояние, в котором он не выполняет sync. Локально не запускать `npm run sync` или `npm run bot` параллельно.

Проверка подключения и текущей структуры выполняется read-only:

```powershell
node scripts/postgres-migration.mjs --check
```

Скрипт выводит только агрегаты: количество задач, статусы, размеры JSON, диапазон ID, количество tombstones и контрольные hashes. Содержимое задач и connection string не выводятся.

Если Aiven пустой, проверка сообщит это и ничего не изменит.

## Копирование данных

После остановки бота выполнить:

```powershell
node scripts/postgres-migration.mjs --apply --confirm-source-frozen
```

Скрипт:

- проверяет, что исходная схема имеет версию `5`;
- читает источник в одной read-only транзакции;
- создаёт стандартную схему приложения на пустой Aiven-БД;
- переносит все поля задач, статусы, даты, fingerprints, snapshot’ы, metadata и Classroom tombstones;
- восстанавливает sequence `homework_tasks.id`;
- отказывается перезаписывать непустую или неизвестную целевую базу;
- повторно сравнивает источник и Aiven после копирования.

При любой ошибке целевая транзакция откатывается. Neon не изменяется.

После успешного копирования повторить проверку:

```powershell
node scripts/postgres-migration.mjs --check
npm test
```

## Переключение Render и локального окружения

Только после успешной проверки:

1. В локальном `.env` заменить значение `HOMEWORK_DATABASE_URL` на Aiven Service URI.
2. Удалить временные `SOURCE_DATABASE_URL` и `AIVEN_DATABASE_URL`, если они больше не нужны локально.
3. В Render изменить `HOMEWORK_DATABASE_URL` на тот же Aiven URI и добавить `HOMEWORK_DATABASE_CA_CERT` со всем содержимым скачанного CA-файла. Для Render не использовать путь `HOMEWORK_DATABASE_CA_CERT_PATH`, потому что локальный путь там отсутствует.
4. Сохранить изменения и выполнить один restart/deploy.
5. Не запускать второй bot-процесс. Telegram long polling должен иметь одного владельца.

При первом реальном запуске бот может обработать уже сохранённые `notification_pending` записи. Поэтому cutover следует выполнять только тогда, когда допустима обычная доставка накопившихся уведомлений. Подготовленные проверки до этого момента Telegram не вызывают.

## Откат

Если Aiven не принимает соединения до первой новой синхронизации:

1. Остановить Render-процесс.
2. Вернуть прежний Neon `HOMEWORK_DATABASE_URL`.
3. Выполнить один restart/deploy.

Neon нужно держать нетронутым до подтверждения стабильной работы Aiven. После того как на Aiven уже появились новые записи или статусы, простой возврат ссылки может потерять изменения, поэтому сначала потребуется отдельная обратная копия данных и повторная проверка.

## После успешного периода наблюдения

В течение первых 24–48 часов проверить в Aiven CPU, RAM, свободное место, подключения, логи и график сети. Для анализа запросов доступен `pg_stat_statements`, если расширение включено.

После этого можно удалить временные переменные и, если Neon действительно больше не нужен, отдельно удалить его только после финального резервного решения. Не удалять Aiven или Neon как часть автоматического скрипта.
